# Socra UI audit, 2026-10-25

Branch `phase-8/ui` (HEAD `0b20068` plus the uncommitted redesign). Phase A of the final UI wrap-up: read-only on code.

**How it was done.** The running app was compared with `docs/design/mockups/socra-mockup.html`, `docs/design/mockups/socra-admin-mockup.html` and `docs/legal/socra-legal-copy.md`, and the code was read against the checklist. The app ran in a separate compose project (`socra-audit`, ports 7100/7110) with no Supabase URL, no provider keys and the fake LLM (`tests/e2e/fake_llm_server.py`), so the dev stack and its data were never touched. A Playwright script walked every public, learner and console screen at 1280 and 400 px, light and dark, and recorded console output and horizontal overflow.

- **Screenshots**: 224 files in `docs/design/audit/2026-10-25/` (gitignored). Key ones: `landing`, `lesson-book`, `quick-check-card1`, `test-results`, `console-overview`, `stop-dialog`, `failed`.
- **Measured**: 0 pages overflow horizontally at 400 px. 0 hydration or React key warnings. 49 console errors, all of them failed resource loads (401 on `/api/auth/me` and `/api/auth/refresh` for signed-out visitors, plus the expected 404 on the not-found page).
- **Not checked**: the dashed "Mockup controls" bar (ignored, as instructed). Pixel-level comparison of every screen with the mockups: the screens were compared by eye, and the differences found are listed below.

- `make e2e`: 8 browser tests pass against the fake-LLM stack, including Stop then Retry at four moments of a build.
- The sandbox bundle builds, and `bun run typecheck` in `sandbox/` passes (a one-line `declare module "*.css"` in `src/css-modules.d.ts` covers the `mafs` and `katex` stylesheet imports).

### Deferred (approved)

- The sandbox theme message carrying token values (today they are copied into the harness and a drift test guards them; changing it touches the CSP/runtime contract).
- Atomic multi-step routing save in the console.
- CSV export when the session has expired.
- SSE token refresh before reconnecting (it already degrades to polling).
- Pausing the landing walkthrough while it is off-screen.
- Added while fixing: console run retry stays outside a transaction (its docstring says why: the worker has to find the run as soon as it is queued). Writing its audit entry in the same transaction needs the dispatch moved to `on_commit` in `RunDispatcher`, which changes every test that reads the queue; a failed audit write after a successful retry is the only gap.
- Added while fixing: the browser tests are not in CI (the workflow has no browser or compose-in-compose step); `make e2e` is run by hand.
